# 提示词与随机维度审计（2026-11-09）

## 结论

提示词详细不会让 Python 停止抽取。需要区分三件事：
1. 候选是否可达、轮换是否正常：可以用程序验证。
2. 候选是否表达不同画面：要看机位、位置、轮廓、景别等视觉差异，不能只数句子。
3. 出图是否有区别、是否保留产品：必须用相同参考图实际对照，不能拿测试通过代替。

本轮实施低风险修复与默认提示词精简，没有删除维度、取消手选或改写用户自定义内容。实际生图效果尚未做新一轮对照，材质不继续扩大修改范围。

## 维度职责与联动

| 范围 | 实际维度 | 保留的配合方式 |
|---|---|---|
| 开业买家秀 | 12项，行业文案另行管理 | 行业决定品牌、Logo和经营环境；室内/室外决定装修、摆位、气球固定、镜头 |
| 开业商业效果图 | 12项 | 商业展示空间/背景层次替代城市/地址；75–150mm镜头池优先，场地仍按室内/室外 |
| 七个其他场景，买家秀/商业 | 各10项 | 场地边界固定；商业模式不抽生活人物，使用主体展示构图 |
| 开业近景 | 12项 | 对象/材质是自填输入；先选镜头类别，再选兼容机位、裁切、焦点、景深 |
| 其他场景近景 | 各11项 | 共用近景语义，使用原场景存储槽位；没有单独“对焦层次”行，景深由镜头/焦点描述承担 |

近景共有3类镜头、11个机位、9个局部构图、6个焦点和6个景深候选。不是所有组合都应该可用，例如垂直俯拍与沿面斜拍的景深不能乱拼。锁定套内的机位或构图会缩小随机范围，这是联动要求，不是失效。自定义句子无法可靠自动判定物理含义，仍保留人工输入。

反光强度与位置保持现有联动：哑光配无光带；有光带时选兼容强度。隐藏控制输出，不等于解锁。三个模式是不同成像目标，不能把买家秀手机摄影的要求带入商业或近景。

## 本轮已修改

### 1. 商业摆位恢复完整候选，画面位置只由构图负责

之前七个商业场景对原摆位只取前8项，再乘4条“居中/偏左/偏右/分层”，得到32条。原池是40条（8个位置及其摆放变体），其中32条摆放变体没有进入商业池。

现在使用完整40条实际摆位。装置“放在哪儿”和主体“在画面哪儿”分开：主体展示构图承担画面左右居中，摆位不再额外叠加相反指令。

旧版精确预设值会迁移，原有效锁定保留；完整旧默认覆盖池升级回新默认。用户手写候选保留，不通过关键词模糊删除。

### 2. 优先抽取不同的基础方案

行业候选之前可能连着抽到“同一装修；细节一”和“同一装修；细节二”。现在优先从剩余轮换袋选分号前基础方案不同的候选；没有其他基础方案时仍抽剩余项。

这不删除候选、不破坏用尽再补充的轮换，也不是全局固定概率均匀抽样。强随机的目标是减少连续相似，不是证明各类画面概率完全一样。

### 3. 精简固定提示词

- 买家秀：保留普通手机、正常机位、现场光、完整装置和不额外做地面反光等规则。
- 商业：保留75–150mm及左右前方视角；按本轮光线布光，删除固定“均匀光”与随机光线竞争的要求。
- 近景：保留单反棚拍、90–105mm成像参考、主要细节+相邻结构；删去重复保护与设备操作说明。没有改变原稿决定图文的原则。
- 物理尺寸只在产品尺寸段指定，不在默认固定要求里重复3.5米。
- 明确参考职责：产品原稿管图文与形状、实物材质图管表面、拍摄样片管机位与光线。工具仍是离线文本工具，不读取图片。
- 明确这些是已经抽定的本轮参数，复制到聊天生图后不用再次随机改写；未指定细节可在现有限制内安排。
- 近景前后层次不要求模型增加叠层，只呈现已有关系。

只更新默认模板，手改固定要求、补充要求、手改整段提示词都保留。已保存的自动生成场景提示词重新组成，避免重启后仍显示旧缓存。

## 抽样与验证

基线：4558f41；固定随机种子41。三种模式×八个场景×每组60次，共1440份提示词；开业以美业为样本。字符数是 Python 字符串长度，含标点与换行，不是 token 数。前后同种子与流程，因抽取策略变化，所选参数不完全相同。

| 模式 | 改前平均字符 | 改后平均字符 | 约减少 |
|---|---:|---:|---:|
| 真实买家秀 | 1089 | 897 | 18% |
| 商业效果图 | 1323 | 989 | 25% |
| 近景摄影 | 781 | 692 | 11% |

开业场景单独比较：买家秀1508→985，商业1588→987，近景804→715。
每个场景/模式内60份文本均不同。近景跨场景使用相同摄影模型，在相同种子下出现相同文本是预期行为，不能当作独立的480套新摄影方案。

验证结果：
- 115项自动测试通过，包括新增9项回归测试：完整摆位可达与用尽轮换、基础方案优先、旧锁定迁移、用户候选保护、缓存升级/手改保护、模式边界、近景套系与隐藏、完整自定义要求。
- Python编译检查通过。
- 自动测试在当前云端Python环境执行，不能替代Windows实际运行。
- 未进行Windows GUI实机测试；未做本轮实际生成图片对照。自动检查不能证明材质准确或图片随机性提高。

## 尚未实施，供选择

| 优先级 | 方案 | 解决的问题与取舍 |
|---|---|---|
| 1 | 一键生成4套不同方案 | 保持同一产品/材质，在镜头类别、构图方向上拉开差异，再逐套复制出图。最符合以随机为主的操作；需增加多方案预览与选择，生成工具仍不自动调用生图服务。 |
| 2 | 近景辅助项合并 | 将邻接边缘、局部留白、外观保留等合并为更明确的构图意图。减少同义候选；需要迁移原有锁定/隐藏和编辑池，因此本轮没有直接删行。 |
| 3 | 主变化优先随机 | 一次优先改变大构图/空间风格/机位，少量改变辅助项，更容易看出差异。会改变现在全部未锁定项一起抽取的行为，需选择是否采用。 |
| 4 | 材质外观单独保存为预设 | 记录用户确认过的简短外观描述与参考图用途，再随机布光；避免每次写长文。材质名不能替代实物参考，也不能保证单凭文字识别不同写真布。 |
| 5 | 行业品牌候选扩充 | 当前每行业8个品牌、6个Logo形态，组合后文案很多但品牌本体较少。“品牌和街道随机组合”在行业路径中实际只有街道进入组合生成，品牌仍优先行业池；需决定扩展行业品牌库，还是恢复可选择的组合品牌生成，不能直接混入不符行业的名字。 |
| 6 | 场景交叉规则和自填锁定专项 | 如装修风格与入口结构、材质与铺地分格、手填值在切换行业/模式后的保留，都有进一步检查空间。可加有针对性的规则；不宜靠全句关键词猜含义或大量限制来牺牲随机性。 |

另外，近景主体可以自定义为杯子等立体物，但当前三套镜头主要来自平面印刷品参考。若要常拍立体商品，应增加“平面印刷品/立体商品”模型，避免用长边、平面边饰类构图套所有产品。这个改变涉及模式范围，本轮不默认添加。

## OpenAI提示词依据

已核对官方文档：
- https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide
- https://developers.openai.com/api/docs/guides/image-prompting

采用其明确目标、简短分段、区分保留与修改、标明参考用途、逐项检查的思路。相机参数作为画面方向提示，不能当作精确物理仿真。文档不是“越短越好”的依据；本轮删的是重复与竞争要求，而非必要的产品约束。

你主要在聊天中生图，因此未接入API，也没有向文本中塞入quality、seed或complexity参数。后续真正的出图验收，应使用同一产品原稿和材质实拍，分别比较三类机位，而不是只比较不同的生成示例。
