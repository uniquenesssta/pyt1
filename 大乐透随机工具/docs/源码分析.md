# 上传源码分析与整合

分析对象：`大乐透.zip` 中全部 9 个 `.py` 文件，合计 3415 行（按 `splitlines()`，不含任何外部历史数据）。读取了全部源码，并对两个大版本进行 AST 方法级比较；没有执行用户源码中的文件改写或其他外部操作。

## 关键整合决策

1. 一个入口、三个主页面，而不是把九个脚本按按钮启动。数据只读一次，所有模块共享同一批校验过的记录。
2. 保留原来有效的业务能力，不复制已证实错误的实现。结构概率改称“相对权重”，而不是维持不真实的目标百分比界面。
3. 均匀随机完全不受导入历史数据影响。系统随机源解决种子可预测问题，但不提高彩票中奖概率。
4. 不沿用来历不明的固定历史权重；历史模式必须有用户导入数据。加一平滑只用于生成，报表不改原次数。
5. 保留固定号码，但以“固定”命名，不把普通复式错误标成正式胆拖票。费用按组合数实时计算。
6. 统计图由标准库 Canvas 绘制，减少原 numpy/matplotlib 安装与中文字体依赖。
7. 生成、导入、查询在线程中执行，主线程只接收结果；取消或失败不会清空上一次完整数据。
8. 批量结果分页只是显示分页，不是生成上限。一次最多10000组，导出全部结果，避免复现“只能显示50条”式的限制。

## 限制与取舍

- 未提供真实历史开奖数据，因此测试使用显式标注的合成数据验证算法；应用不附带模拟历史。
- 不提供联网开奖抓取、开奖预测、自动购买或奖金判定，原脚本也没有完整实现这些功能。
- 历史结构加权是新统一的明确模型，不声称与旧版错误算法逐位输出一致。
- 暂不保留上次随机结果或历史文件的自动加载，仅收藏持久化；每次启动默认回到均匀随机。
- CSV 只接受文档说明的原始7/8列结构；不擅自猜测日期、奖金、网站说明列。
- 收藏数据保存在工具目录，需有写权限；不会写入其他工具目录或用户仓库之外的位置。
